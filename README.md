用于《英雄没有闪》微信小程序刻印界面的视觉辅助工具。支持手动选择，以及自动扫描五列刻印列表、强化、筛选并保留或分解。启动默认为**自动扫描、开启强化、强化 2 次、红字阈值 ≥20%、开启未出现第三种元素时保留**；打开软件或更改模式不会立即开始或发送游戏输入，仍需按 F9 开始。

## 功能

- F9 开始、暂停按钮或 Esc 暂停、F10 停止、F11 调试。
- 自动扫描只处理本轮打开时恰好有 2 个属性的刻印，原有 3/4/5 属性一律跳过。
- 原本已有 5 个属性的刻印禁止分解；本轮从 2 个强化到 5 个的刻印按筛选结果处理。
- 自动或手动确认分解。
- 可固定强化 1、2 或 3 次。
- 红色词条达到阈值时保留；没有红字且开启元素保留开关时，强化后没有出现第三种元素也保留。
- 当前刻印和五种元素统计使用游戏图标显示。
- 中间统计会单独显示红色数字达到当前阈值的刻印数量。
- 在 `logs/` 限量保留最近运行过程，异常时另存错误报告。
- 当前刻印、分解统计使用固定区域；进度与保护暂停原因集中在独立运行状态区，提交日志提示位于模块外。
- 完整扫描、复核完成后弹出“完成刻印自动筛选分解”；材料不足、错误、暂停和安全上限不冒充完成。

## 使用方法

### 开始前

1. 启动游戏，并进入刻印列表界面。
2. 按游戏提示手动勾选“本次登录不再提醒”。
3. 建议将游戏窗口调整为 `550×1020`，并保持游戏窗口可见，不要被其他窗口遮挡。
4. 启动本助手，查看右上角的“当前分辨率”。确认窗口尺寸达到建议范围，并且显示“当前可以使用”。调整游戏窗口后，当前分辨率和可用状态会自动刷新；如果显示“当前无法使用”，请检查游戏是否已打开、窗口比例是否正确，以及当前是否停留在刻印界面。

### 基本操作

1. 如需手动选择刻印，先将“选择方式”切换为“手动选择”，再选择“自动”或“手动”分解确认方式；使用默认自动扫描请参见下一节。
2. 需要自动强化时，打开“自动强化”，并在 `1 次 / 2 次 / 3 次` 中选择一个固定次数。
3. 在红色词条选项中选择阈值：`≥10%`、`≥15%`、`≥20%` 或 `≥27%`，所有流程都包含等于阈值的情况。
4. 打开游戏中的刻印列表，手动点开要处理的刻印。
5. 按 `F9` 开始。助手会识别当前刻印、按设置强化，并根据保留规则进行分解判断。
6. 按 `F10` 停止；需要暂时停住流程时使用“暂停”按钮。

### 自动扫描

1. 保持游戏在**刻印列表**，不要预先打开详情或分解弹窗。
2. 默认已经选择“自动扫描”、开启强化、**2 次 / ≥20%**。可以按需要改选强化 **1 / 2 / 3 次**及红字阈值。
3. “分解确认”是独立设置：选择“自动”可连续处理；选择“手动”则每次由你确认最终分解，取消确认会暂停扫描。
4. 按 **F9** 或点击开始。工具从向上 **2 格**起步，根据每步实际位移校准到约一行；上方仍出现新内容就继续，确认顶部后逐行、从左到右处理合格刻印。不会一次大幅跳顶；若回顶多格导致重叠区域不足，本次回顶减为每次 1 格继续核验。每次保留/分解后重新识别，不沿用旧坐标。
5. 当前页没有可处理的刻印后才下滑，从 1 格起步，依据核验过的真实像素位移自动调整步幅。每步最多加倍、上限 32 格，以约两行（180 参考像素）为目标，同时扣除固定栏、至少一行重叠及 8 像素余量。列表仅约 270 像素高时，目标会限制在约 148 像素，不会强跳两行造成漏卡；也不是固定发送最大滚轮量。普通滚动最短等待 0.3 秒，仍要求三帧稳定画面；不会用拖拽兜底。
6. 如果本段已验证滚动方向及位移，并观察到临近边缘的限位缩短，随后连续两次滚动画面稳定不变，即可确认边界，不再重复往返。首次就在边缘、没有明确限位证据等情况，才反向移动 1 格并恢复 1 格验证响应。普通滚动后突然不响应不能直接判定到底；相同颜色组合或单次画面不变也不作为完成依据。
7. 确认到底且当前无候选就显示“自动处理完成”，不再回顶部复扫；底部还有完整候选时先处理。完成仅指当前筛选列表的本次向下扫描，不额外检查游戏重排到上方的刻印，也不代表其他筛选类型已处理。

自动扫描正常保留达标刻印后会继续。界面显示阶段、已处理、本页候选、滚动次数和扫描遍数；“本页候选”不是总库存数，也不会把相同颜色当成同一枚刻印。

#### 安全边界与暂停处理

- 每次选卡要求五个槽位完整识别：恰好 **2 个彩色槽 + 3 个明确的灰槽**，不是“没识别出颜色就当作灰槽”。未完全显示的卡片不点击。
- 列表与详情的原始两个属性必须顺序一致；详情需连续稳定，强化必须实际观察到 `2→3→4→5` 的逐次变化。只数点击次数不算成功。
- 分解及确认均要求有效的本轮初始 2 属性记录。选卡、强化、分解、确认发送前再次截图校验，点击关闭抖动。
- 红字读取不清、属性/刻印名称变化、材料不足导致的超时、异常弹窗、窗口失焦/移动/缩放、设置变更会暂停。不会在超时后重复强化或重复确认。
- 暂停、停止和重新开始会撤销处理记录。**回到列表后按 F9 重新扫描**；中断时已经强化到 3/4/5 属性的刻印不会被新一轮接管，请人工检查。
- 无法确认滚轮响应、向下滚动跨过可核验重叠区、边界仍有被遮挡卡片时，显示保护暂停，而不是宣称全部完成。回顶时多格重叠不足只允许减为 1 格再校验，仍无法核验则暂停；这次未知移动不算到顶证据。请检查窗口是否完整可见及系统滚轮设置。
- 小库存只有在完整卡片下方存在明确的大片空白列表区域时才按单页处理；最后一枚分解后，还会核对原列表工具栏、空白区域和已确认分解数量。无法区分“列表已空”和“识别失败”时暂停。
- 一轮默认最多处理 1600 枚、滚动 1200 次、运行 2 小时；达到上限表示暂停，不表示已全部完成。这些上限位于 `src/imprint_decompose/default.yaml` 的 `automatic` 配置中。
- 运行期间不要手动滚动、切换刻印、改变筛选/排序或用其他软件抢占游戏窗口。相同外形、相同属性的不同刻印没有可读取的唯一 ID，视觉校验不能代替保持操作环境稳定。

自动选卡复用手动版的截图归一化、详情识别、OCR、按钮坐标和保留规则，参考窗口仍为 `550×1020`。三张用户提供的裁剪图仅用于识别回归，不作为完整窗口点击坐标标定。真实游戏端到端及不同缩放尚需用户实测；若提示边界识别失败，请提供完整窗口截图进行校准。

### 保留与分解规则

- 关闭“自动强化”时，助手直接判断当前刻印。
- 开启“自动强化”时，助手最多按所选次数强化，每次强化后重新识别新出现的元素和词条。
- 检测到达到所选阈值的红色词条时，保留当前刻印并提醒。
- 完成设定强化次数后，没有红色词条时，只有保留原始颜色且总颜色不超过两种才按颜色规则保留；“保留未出现第三种元素的刻印”默认开启，关闭后不再按此规则保留。手动选择与自动扫描、分解前重新截图核验均使用同一规则。
- 更改此开关会暂停当前处理并撤销旧授权，需回到列表重新开始；不会沿用更改前的分解决定。红字达标、数字不清、原有 5 属性保护不受开关影响。
- 已识别到低于阈值的红色词条时，不再用颜色规则将其判为达标；手动确认及历史保护检查仍可能要求人工处理。
- 当红色数字无法可靠识别时，保护保留，交由用户检查，避免误分解。
- 红色数字识别采用“游戏字模高速识别 + PP-OCRv5 轻量模型低置信度兜底”；OCR 模型随 EXE 打包，不需要联网或另装 OCR 环境。
- “自动”确认模式会自动处理普通分解。手动选卡时，保留后等待用户选下一张；自动扫描时，正常保留后继续扫描，识别不确定时暂停。“手动”确认模式下，所有分解都由用户完成最后确认。

### 运行状态与日志

- 右上角会动态显示检测到的“当前分辨率”；找到游戏窗口且分辨率合格时显示“当前可以使用”。进入刻印页面后，助手仍会先通过视觉识别确认页面状态，再执行操作。
- 当前刻印区域会显示识别到的元素组合；下方统计记录本次运行的分解数量、保留数量、红色达标数量，以及组合种类和总数量。
- 正常退出和重新启动不再删除过程日志。`tower_bot.log`、`imprint_decompose.log` 各约 1 MB，分别最多保留一份 `.1` 轮换备份，两类过程日志合计约 4 MB；错误报告单独保留。
- 过程日志包含启动版本、退出结果、实际选卡模式变更、输入动作及保护停止原因，便于区分“控件显示异常”和“执行模式真的改变”。
- 自动扫描保护暂停时，在 `debug/` 保存 `imprint_auto_safety_stop_latest.png` 和带时间的诊断截图；另以固定文件名覆盖保存 `imprint_auto_failure_*_latest.png` 原始截图/滚动前后区域及 `imprint_auto_failure_latest.json`，用于无标线干扰的回放。JSON 的 `images` 指明本次有效图片，未列出的旧图片不属于本次错误。F11 连续调试仅覆盖 `imprint_latest.png`，不逐帧堆积图片。
- `AUTO_TRACE` 记录阶段、卡片数量、槽位不确定原因、实际位移、截图/识别耗时；`AUTO_VIEWPORT` 记录避开底部导航栏后的列表区域。输入日志同时记录滚轮刻度和 Windows 原始滚动量。
- 如果助手停在某个刻印上，请先查看界面提示；无法识别数字时不要强行继续，手动确认后再处理下一个刻印。

## 本地运行与构建

要求 Windows 和 Python 3.11。核心历史模块来自 Python 3.11 字节码，因此目前不能使用其他 Python 大版本。

```powershell
python -m pip install -r requirements-build.lock
./build.ps1 -Python python
```

构建结果位于 `release/yxmys-imprint-assistant-v版本号.exe`，是可以单独发布的单文件 EXE，不再依赖旁边的 `_internal` 文件夹。构建使用固定的 `build/work` 和 `build/stage`，先运行回归测试，再检查 EXE 界面、阈值设置和 OCR 模型加载；全部通过才发布。`release-info.json` 记录版本、源码提交、SHA256 和自检结果。

Windows 本机和 GitHub 托管环境的可选系统字体数量可能不同。字模回归逐张核验仓库内 0～9 的原生字模、加载顺序及识别结果，不依赖本机字体总数；另覆盖没有系统字体的环境。CI 使用 UTF-8 输出，并在失败时上传已有的测试日志、打包警告和 EXE 自检报告（保留 7 天），测试及 EXE 自检失败仍会阻止发布。

- `AUTO_TRACE` 与失败 JSON 增加边界确认方式、静止次数和限位证据，便于继续排查速度和结束行为。

## v3.5.0 强化结果稳定性与单页界面优化

- 针对第二次强化后属性记录不一致：新增槽位必须像素与元素同时稳定至少 0.35 秒、连续至少三帧，且距本次已确认发送的强化点击至少 0.65 秒，才提交本轮记录。后续步骤复用这份稳定结果，保留最终词条核验和动作前新截图检查，不重试强化、不放宽原有属性保护。
- 保留开关默认开启；自动、手动强化后判断及自动分解前复核均生效。关闭后仅取消无红字的双元素保留规则，不取消红字/未知属性保护。
- 完成事件使用递增编号，仅在安全状态机确认完成后触发一次弹窗；普通刷新、暂停、超时及错误不会重复或误报完成。
- 固定当前刻印和分解统计区域；独立状态区集中显示进度、错误摘要及提交 `logs` / `debug` 的提示，完整错误仍保存在日志里。长文字不会撑大窗口。
- 窗口先隐藏构建，测量最终尺寸后一次显示，取消启动时临时 820×900 窗口、透明度和强制置顶切换。本机 125% 缩放布局为 780×730，无滚动条。
- 原始失败证据新增预期/实际元素、初始属性、已完成次数和筛选设置；强化成功日志同时记录实际元素。离线回归不消耗游戏材料，新版实机连续运行仍需用户复测。

## v3.4.8 强化横幅误判与节奏修复（历史版本）

- 日志确认首次强化已从 2 属性变为 3 属性；专精升级横幅遮住了旧图案校验区域，导致错误保护暂停。改为以识别到的属性行定位静态名称区域，避开专精横幅、等级数字和评分；仍复核名称、原始属性顺序及每次只增加一个属性。
- 打开详情和强化结果需连续三帧、至少 0.18 秒稳定；成功后复用这份稳定结果，不再重新等一轮。最终红字筛选仍要求至少 0.4 秒稳定，强化及分解前仍重新截图复核，不盲目连点。
- 下滑目标由约一行提升到约两行，受可见区域与重叠区限制自动收敛；回顶仍保持较小目标。保留每方向已验证的较快像素响应，避免在底部被截短的一次移动导致下一遍错误加大步幅。
- 诊断新增固定名称区域的前后图片及差异值，均为固定文件名覆盖保存，不逐帧堆积。
- 自动扫描、强化 2 次、20% 默认设置不变。旧版本暂停时已经强化到 3 属性的刻印，不会被新一轮自动接管。

## v3.4.7 实际位移校准

- 真实游戏中一格滚轮可能只移动 4～7 像素；改为用已验证的位移校准步幅，而不是固定一格反复等待。回顶和下滑均限制渐进增幅、最大刻度与可验证重叠区域。
- 滚动匹配排除列表顶部混入的固定工具栏边缘，避免相似刻印图案产生错误竞争；仍拒绝无法区分的重复行，不降低匹配置信度要求。
- 支持辨认真实 2～4 像素的微小边界移动，保留三帧稳定、往返边界确认及单像素抖动不作为移动证据的保护。

## v3.4.6 小步回顶

此版本的固定步幅已由 v3.4.7 的实际位移校准替代；以下为历史变更。

- 取消启动/复扫时一次 `+240` 格的大幅滚动，改为每次向上 2 格、逐步观察，直到连续上滚不再出现新内容；保留小幅往返边界校验，避免把输入失效当成到顶。
- 每步最短等待 0.3 秒且必须连续三帧稳定；2 格重叠不足时自动降到 1 格，方向异常或降步后仍无法确认会保护暂停。向下仍每次 1 格。
- 自动扫描、强化 2 次、20% 的启动默认值不变；F9 才开始操作。

## v3.4.5 启动默认设置

- 默认选中自动扫描、自动强化 2 次、红字阈值 ≥20%，控制器与界面初始值一致，不再先显示旧的手动/1 次设置。
- 只改变启动预设：仍需 F9 才开始，不自动点击或滚动；手动模式和其他次数/阈值仍可选择，暂停和继续不会重置用户本次选择。
- EXE 自检直接验证首次打开时的实际控件值及未启动状态。

## v3.4.4 滚动节奏优化

此版本的大幅回顶已由 v3.4.6 的 2 格小步回顶替代；以下为历史变更。

- 首次回顶和处理后的完整复扫，先发一个大幅向上的滚轮事件，再做短暂的顶部校验，不再从库存底部逐格爬回顶部。大幅移动不计为扫描完成，也不授权选卡；只有回顶允许跨页。
- 普通滚动最短等待由 0.4 秒降到 0.3 秒，列表稳定观察由 0.25 秒降到 0.20 秒，三帧稳定要求不变。大幅回顶另等至少 0.55 秒，动画未停稳继续等待。
- 向下仍一次一格、保留至少一行重叠；强化、红字筛选、分解二次复核和原有 5 属性保护均未改动。

## v3.4.3 初始化、滚动与列表识别修复

- 按旧版识别优先级先判定页面，仅详情页读取红色词条及加载 OCR。列表页不再对已装备刻印的图案执行无用 OCR；详情红字阈值和读不清时保护不变。
- 已在顶部时，边界验证从 8 个滚轮动作减为 4 个：两次静止、反向探测、返回同一画面。保留真实往返移动证据；到达底部后只有本遍处理过刻印才需要完整复扫。
- 将画面停稳与槽位完整识别分开，容忍 1 像素识别坐标抖动；每次滚动仍等待至少 0.4 秒并要求连续稳定画面。复用已稳定截图，不在切换回列表阶段后再等一遍。识别不完整时不得继续下滑、选卡或宣称完成。
- 修正图案/等级碎片被误认成另一排槽位、漏识别中间列时第五列编号错误的问题。开始时检测并排除侵入列表区域的固定底部导航栏，避免把被导航遮住的槽位当成完整行识别失败；部分行仍不点击。
- 按阶段报告超时原因，滚动失败不再误报“可能材料不足”。保留原图和滚动前后图，日志包含识别耗时和具体漏识别位置，便于复现。
- 回归覆盖不同滚动位置、缺失灰槽、缺失列、坐标抖动、动画未停稳、边界动作数量、分解保护及原图保存。均为离线/模拟输入测试，未操作游戏；真实游戏与不同缩放仍需用户实测。
